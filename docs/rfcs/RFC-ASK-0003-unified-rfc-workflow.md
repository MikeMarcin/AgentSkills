# Unified RFC implementation and attended workflow

The user approved the complete design and Q1–Q13 answers with “Implement the plan”.
Authoritative design: the scope and acceptance contract in this RFC.

Unify implement-rfc, attended-review and wizard in AgentSkills, with external repository facts and one model policy. Use ordinary focused validation and one warranted integration pass; no default exhaustive matrix, hermetic replay or manual approval ritual. Migrations are explicitly authorized for all six consumers, one-off and outside durable skills. Preserve unrelated dirty product work and historical truth.

## Acceptance

**RFC-ASK-0003-AC01** One canonical versioned multi-RFC card model, scoped queue and shared configurable single/per-area allocation support all named consumers; historical converters are one-off only.

**RFC-ASK-0003-AC02** Explicit claim and acceptance-driven finish commit only supplied scope; compact evidence, scoped checks and integration-focused verification preserve agent judgment and efficiency.

**RFC-ASK-0003-AC03** Portable attended sessions persist partial decisions, expose human waits, incrementally prepare candidates, protect relevant resources, resume development selectively, and support concurrent checkout hosts with both drivers and offline HTML fallback.

**RFC-ASK-0003-AC04** A portable wizard presents one manual step at a time with durable progress and HTML/CLI paths; native Windows has no Bash or WSL requirement.

**RFC-ASK-0003-AC05** AgentSkills, MASK, SRV, SampleLogs, SamplePlanner and sample_studio consume the shared skills through guarded MASK deployment; all live cards including history are normalized without fabricated completion or unrelated product changes.

**RFC-ASK-0003-AC06** Focused public-path tests plus one integration pass exercise persistence, isolation, concurrency and native portability; provenance records actual checks, commits, limitations and cleanup.

## Non-goals

No publication/push, application-wide revalidation merely for metadata, persistent daemon, MASK script execution on install, per-project skill forks, cross-project attended dashboard, or fabricated historical evidence.
