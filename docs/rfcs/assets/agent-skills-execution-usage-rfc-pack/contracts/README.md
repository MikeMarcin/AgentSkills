# Contract examples

Schemas define proposed boundaries, not implemented runner behavior. Production
runtime adds the semantic checks in each RFC; JSON validation alone never grants
authority, proves safe paths or accepts a result. Native identifiers are local-only
and must be projected safely into usage exports.

Every example work order is explicitly `example_only: true`, with synthetic revision
and routing values. It must be rejected by a real `start` operation. The scout trace
is a **synthetic expected ordering**, not evidence that a real recovery occurred.

`execution-selection.v1` is new consumer-generated opt-in state, separate from
project facts. Add shared `config/routing-profiles.json` to retain the existing
routing.json baseline; profiles do not edit the baseline deep reviewer class.
