# Bounded native qualification

## Purpose and cost boundary

Demonstrate real plan discovery and multi-card continuation on both selected
interactive drivers, Claude and Codex. This is not a provider benchmark or a quota
savings experiment. Preserve existing selected coordinator/integrator/review routes;
do not substitute a cheaper model and call the configured route qualified.

Prepare and run all deterministic tests before using model capacity. Plan two short
initial courses total, one per supported native interactive driver, within an
explicit owner-approved capacity/time ceiling already available to that environment.
This packet's authoring is not permission to buy capacity, enable API billing or
create an external supervisor. Account for any independent qualification sessions
separately from implementation usage. Stop at the agreed ceiling with partial work
preserved; further failed-course retries require a reason and available authority.
A small correction can resume its actual producer instead of resetting the course.

Do not run one paid session for every scenario in `fixtures/scenarios.json`.
Unavailable runtime or approved capacity is a real pending acceptance condition,
not a mock pass. No new human acceptance requirement is added to the example code.

## Preparation

Use task-owned small Git repositories, existing native tools and a selected immutable
candidate skill snapshot through actual supported discovery paths. Do not copy a
stale role file from the source dump. Check the actual native role definitions and
record how the host selected them; preserve addenda and configured routes. Verify
quiescence and isolate candidate ownership. Never edit a real product board for a test.

The example `fixtures/raw-pack/` supplies six tiny issues in two milestones for a
small dependency-free Python name-catalog CLI. The issue headings misleadingly name
individual milestones. Only the canonical authored plan defines grouping. Provide
normal applicable repository instructions and this raw pack; do not add test-only
prompt coaching that supplies the correct grouping or `continue` answer.

A test harness/operator may observe events and stop/resume at a safe boundary, but
must not pre-run plan discovery/adoption or mutate intermediate output into the
correct answer. The tested normal skill entrypoint performs those operations.

## Each driver's course

Use one interactive coordinator to implement the raw target. The first integrator
must discover/adopt the supplied grouping during its authorized intake and implement
the first three-card outcome without replacement or a forced coordinator round trip
for each card. It preserves actual card claims/verification. Its accepted boundary
can hand the second outcome to a fresh integrator with that recorded reason. The
second group finishes tests/docs and closeout in its own engineering context; no
administrative successor is required.

The course should observe at least one ordinary partial/progress event before the
first milestone is accepted, and at least one safe resume. Prefer a genuine native
turn boundary or safe operator pause; a result with a live writer is not quiescent.
Where the host cannot resume that native context, record a genuine recovery reason
and unfinished-scope transfer. Do not falsify same-context reuse. The offline test
still covers supported same-ID resume; the native limitation is explicit.

After the authored target, request one small ad-hoc fix with no pack plan in the same
coordinator (e.g. preserve a name's display case while detecting duplicates case-
insensitively). Keep it a tiny independent requested scope; the first responsible
engineer forms and performs it without a separate planning agent or invented RFC.
This follow-up tests fallback behavior, not invalidation of the already adopted plan.
Record the actual boundary rather than forcing an exact generation count across
unrelated targets. A whole course should be small enough that the test's orchestration,
not application complexity, is what is being examined.

## Evidence to keep

Keep compact records of the actual target, candidate source/role versions, discovered
and adopted plan IDs/mapping, assignment milestone/obligation identities, native
producer/dispatch IDs, route requested and observed where available, intermediate
card events, completion evidence, replacement reasons, resume behavior and cleanup.
Inspect actual dispatches and file effects; banners alone are insufficient. Preserve
full native transcripts only in the user-local evidence location under existing
privacy policy, not in committed example files or the coordinator prompt.

Report actual input/context/response counts when available, including all course
children and corrections, with unknowns explicit. They are diagnostic, not subscription
debits. A structurally conforming completion record does not replace checking the
small CLI works and its intended scope was actually delivered.

The pass property is: authored grouping survived discovery/import/execution/resume;
intermediate card labels did not cause fresh generations; a real integration boundary
and a reasoned context action were observed; planless fallback acquired and used its
own useful context; required acceptance and exclusive ownership remained intact.
An unexplained card-driven restart is a failed criterion, not a successful run with
an amusing transcript. Investigate once using captured evidence before spending on
a rerun. Clean only task-owned fixtures after their relevant results are consumed.
