# Focused workflow cases

The [24 cases](fixtures/coordination-cases.json) are acceptance inputs, not a claim
that a model has obeyed them. Read each through the **actual rendered** coordinator,
integrator and leaf instructions. Record the next action and required material.
A small fixture/mock can prove a helper's identity or parsing rule; it cannot
prove native context isolation, scheduling behavior or model judgment.

| Common path | Expected loaded workflow | Check |
|---|---|---|
| New pack / multi-RFC | Coordinator plus handoff; integrator milestone procedure; import reference only at import | First usable integrated result, then fresh successor; original scope survives |
| Resume / correction | Current continuation, live scope and original baseline; same milestone context where available | No replay or accidental new owner |
| One-card implementation | One integrator, relevant code/criteria, focused verification | No required team or multiple artificial milestones |
| Status only | Scoped board/closeout lookup | No source mutation or child session |
| Review only | Direct native reviewer, read-only candidate and criteria | No integrator needed; no implicit implementation/acceptance authority |
| Attended preparation / intake | Attendance reference and current candidate/decision | Required human acceptance open; independent work continues |
| Closeout | Live criterion evidence and verification/closeout reference | No redundant checks of unchanged evidence or fabricated pass |
| Native limitation | Selected host capability and explicit fallback branch | No silent headless/API substitution or inherited low engineering effort |

Use all cases for a focused editorial/helper review. Native qualification needs
only the [two-milestone course per driver](NATIVE_QUALIFICATION.md), including the
relevant correction/ownership/wait events, plus targeted follow-up for an actually
unobserved required runtime behavior. Avoid running 24 paid model sessions.

The coordinator normally sees user scope, IDs and milestone returns. An integrator
sees the relevant RFC/card sections, code and current decisions. A worker sees its
whole assigned slice, not the pack's future milestones. A reviewer sees the exact
candidate/criteria and independent evidence, not an implementer's persuasive story.
Consumer/root instructions remain applicable; reported prompt counts must include
what was actually loaded, not just this packet's shortest file.
