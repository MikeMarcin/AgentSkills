# Native interactive qualification

Required cards: ASK-0054 (Codex), ASK-0055 (Claude). These checks have **not run**
while creating this packet. Qualify an actual supported installed version; do not
substitute an SDK, `codex exec`, `claude -p`, companion launcher, API key or an
external process that restarts the driver. Fixture setup and deterministic tests
can use scripts; the model driver remains the normal signed-in interactive host.

## Select once

Use an explicitly selected, disposable consumer fixture with the candidate skill
source and generated roles. Resolve it through the same installed/shared-link
path as ordinary consumers. A second consumer/context fixture tests isolation;
it does not require another paid model course. Preserve existing native permissions
and trust. The candidate must be coherent before opening the fresh qualification
session; do not overwrite instructions of unrelated active sessions.

Record host/version, selected source revision or dirty candidate identity,
consumer root, requested coordinator and integrator routes, actual observations
where available, and all child identities. Capture baseline usage once. Unknown
native effort remains unknown, not requested=observed. An unavailable required
host remains open. Follow any owner-imposed spending ceiling; no paid retry loop,
subscription purchase/reset, model substitution or extra fleet deployment is implied.

## One small course, two milestones

Create a disposable Python project with a public `catalog.py` JSON CLI and focused
standard-library tests. It manages an in-memory ordered list supplied in input;
there is no server, external service, filesystem persistence or product build.
Its only purpose is to expose a simple cross-milestone invariant and real source
writes, tests and local commits under the ordinary issue-board contract.

**Milestone 1 — add and list.** Add `{id, label}` records and list them in insertion
order. IDs and labels preserve exact Unicode and case. Invalid input is reported
without changing the input list. Use one bounded leaf assignment when native
nesting is available; the integrator consumes its result and exercises the public
CLI. Record the invariant and direct evidence in the milestone handoff.

**Milestone 2 — rename.** In a **different fresh integrator context**, add rename
by exact ID. Renaming preserves ID and insertion order; missing ID leaves the list
unchanged and returns an explicit error. The new integrator consults M1's current
invariants/evidence rather than its transcript. Run only relevant regression and
public-path checks. A required independent reviewer, when used, receives the exact
candidate through native delegation, not an inherited implementation history.

Both milestones run under **one initial interactive invocation**, without the
owner typing “continue” between them. The same coordinator waits and dispatches
M2 after the first completed/quiescent return. Creating two isolated manual sessions
does not satisfy this requirement. Ordinary source edits and local commits are
real fixture work, not generated PASS text.

## What to observe

| Boundary | Required observation |
|---|---|
| Authority | Integrator may perform scoped engineering/Git/board actions; coordinator does not repeat them; leaf authority stays bounded |
| Context | M2 native identity differs from M1; first request is not history-forked; inherited mandatory host material is reported |
| Waiting | Coordinator returns to native waiting, not transcript polling or parallel engineering; count actual coordinator activations |
| Correction | One actual or deliberately supplied concrete same-milestone correction resumes that integrator, not a fresh one |
| Completion | Results and native termination are distinct; successor begins only after accounted quiescence |
| Routing | Coordinator low settings do not override integrator, worker or reviewer settings; report intended/generated/observed separately |
| Continuity | Original scope, amendments, immutable baseline, M1 invariants and exact current candidate survive into M2 |
| Closeout | Actual focused checks and commits recorded; no required acceptance fabricated |

Do not inject unnecessary defects into a consumer product. The correction can be
a fixture-only deliberately incomplete candidate or a real course finding, recorded
as such. Test duplicate/stale/cancellation transition data offline; if the native
stop/resume boundary is not actually observed, state that limitation and select a
single targeted fixture check when needed rather than call mocked cancellation a
native pass. User cancellation is never retried as a normal partial return.

## Runtime-specific checks

**Codex:** verify custom-agent recognition, generated config precedence, explicit
engineering model/effort, child agent-tool availability, wait/continuation identity,
and retained leaf delegation restrictions. Count open descendants against the
actual host limit and retire consumed agents. Do not add guessed config keys for
nesting. Unsupported nesting may qualify integrator-direct work only; exercise
any claimed required-review relay at its actual boundary.

**Claude:** verify ordinary non-fork isolated integrators, the installed host's
foreground/background behavior and nested tool availability, explicit effort
rather than a global low-effort override, exact-agent resumption and completion.
A message to a completed subagent can restart it in current documented behavior;
retirement has no courtesy follow-up. Record any host differences, without
claiming that the source snapshot's minimum version proves every newer behavior.

These are qualification requirements informed by the dated official documentation
in SOURCE_BASIS.md, not a claim of current installed capability.
