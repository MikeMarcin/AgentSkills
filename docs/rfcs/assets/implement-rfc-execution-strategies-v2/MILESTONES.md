# Offline-authored implementation milestones

This is the intended delivery order, not optional regrouping advice. No live cards/IDs are allocated. At intake, map the milestones into the current supported plan format without losing outcomes, exits or dependencies. Refine on material evidence, not merely to create more agents or handoffs.

## M1 — A shared contract and a usable direct path

Extract only the necessary topology-neutral engineering/bookkeeping obligations; add the small strategy selection/registration seam. Preserve the existing coordinator-integrator baseline as one recipe. Implement direct execution with selected readiness, shared plan/evidence checks and truthful continuation.

Exit: direct claim -> product change -> public check -> evidence -> permitted commit works in two disposable consumer contexts with no custom RFC roles; baseline coordinator tests remain correct; read-only branches remain observational. Direct resume and pending external evidence do not create a child or false acceptance. Recipe selection does not load all strategy text.

## M2 — Native Ultra is a genuine alternative

Add native execution with no injected RFC coordinator/role policy; verify scoped host configuration and any necessary small MASK capability handoff. Add native/system-managed provenance and partial/inclusive telemetry cases to existing reporting.

Exit: a bounded authorized native run uses the selected Ultra capability and common bookkeeping without an outer coordinator or bespoke child routing. Native choosing zero children remains a valid outcome. Source/fixture tests are distinguished from actual host capability/loading. Available three-arm trial inputs can now be frozen; no planner-worker model choice blocks them.

## M3 — Another topology without another framework

Register the strong-planner/cheaper-worker strict feedback-loop recipe, scoped role/route requirements and intervention policy. Preserve exact edit/board authority. Add a fifth synthetic recipe as an extension fixture to demonstrate that board/evidence/usage formats do not enumerate the initial topologies.

Exit: registration/conformance fixtures work; malformed/unknown recipes refuse safely; planner takeover and worker route drift are visible; existing direct/native/coordinated paths do not change. Exact worker selection/native qualification is required only before claiming this recipe runnable on a selected host.

## M4 — One real matched block and a truthful readout

Choose an eligible product task, freeze common inputs and selected arms, prepare N source/tracker worktrees, run within explicit budgets, freeze initial candidates, obtain independent blind Astra/Fable judgments, perform the declared repair opportunity and reconcile usage/outcomes.

Exit: observed acceptance, initial/repaired quality, strategy adherence, usage/time/human burden and coverage are recorded separately. Preserve failed/partial runs. No universal topology conclusion or live-main acceptance is inferred. Candidate integration is separately authorized.

M4 requires M2 for the initial three-arm block, and M3 only when planner-worker is selected. Do not make completing every future recipe a prerequisite for the first useful experiment.
