# Roblox asset handoff

## Source and generation

Start with a gameplay key and the object's job in the place. Record its intended size in studs and where it touches the ground, a hand or a station socket. If the experience uses players’ own avatars, their bodies and outfits provide scale and clearance. Model the held prop or NPC named in the brief.

Check the source verdict’s scope. A book plate approved for reference preparation can supply crops for a new input batch. A verdict that already covers the isolated source bytes and generation permits the TRELLIS run. When the project requires another visual decision, put the exact views and a scene comparison in its attended queue and continue work on other admitted assets.

## Export review

Keep the provider mesh and preview with the versioned run. Make a separate derivative at the project’s triangle and texture budget. Place the origin at the agreed grip or ground contact. A rigid prop can use static geometry. Give animated NPCs a suitable custom rig and sample the clips the game uses. Record the forward and up axes and intended dimensions for the importer. [Roblox mesh specifications](https://create.roblox.com/docs/art/modeling/specifications)

For a GLB, run the offline `--audit-glb EXPORT --target roblox` command from **TRELLIS Image to 3D**. When the project calls for export review, use the `game_export` batch gate. Include the exact derivative and relevant texture sidecars in `identity_files` and show a turntable and a view at play scale. Link its decision and audit to the source verdict.

## Studio binding

1. Import the qualified derivative into the development place with **File → Import**. For a local trial, turn off **Upload to Roblox** in the importer. For a shared asset, use the intended creator and record the assigned asset or package ID and version when available. Capture the import settings and any warnings. [Studio Importer](https://create.roblox.com/docs/studio/importer)
2. Inspect the imported descendants. A GLB mesh can become a nested Model with one MeshPart per primitive. Check the actual bounds in studs and pivot against the socket or ground. Inspect the texture and SurfaceAppearance assignments under the relevant MeshParts. Compare at the normal camera distance and under the place lighting. [Importer hierarchy](https://create.roblox.com/docs/studio/importer#gltf-import-hierarchy) · [SurfaceAppearance maps](https://create.roblox.com/docs/art/modeling/surface-appearance)
3. Bind that model to the existing gameplay key. Preserve the project's collision and authority rules. In a streamed place, remove and return to the model’s region during a server-and-client test. Confirm one visual per live entity, correct attachments and an uninterrupted gameplay state. Record the place, instance path or tag, observed scale and collision, and captures beside the exact export digest. For a local trial, record the local place and instance. Leave shared IDs empty until assigned.
