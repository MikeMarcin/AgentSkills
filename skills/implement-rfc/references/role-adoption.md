# Scoped role adoption and rollback

The canonical source now uses standard `rfc-worker`, explicit `rfc-worker-deep`,
normal `rfc-reviewer` and `rfc-reviewer-critical`. The two retired selectors
`rfc-worker-routine` and `rfc-critical-reviewer` refuse new companion dispatch or
route overrides with a migration diagnostic. Historical records remain readable.
Common worker addenda apply once to both workers; legacy routine addenda additionally
constrain standard, and deep addenda constrain deep. Legacy critical-reviewer
addenda are preserved in reviewer-critical. Stricter local constraints are retained
and flagged for owner review, never erased to match the broader shared policy.

## Inspect the selected consumer

Use the current manage-agent-skills skill and the public CLI:

```sh
mask capabilities --json
mask config show --json
mask source status --json
mask project show --project /absolute/selected-consumer --json
```

Record the selected source revision/artifact, declaration and lock state, and the
owned `.mask/generated/implement-rfc/runtime-adapters.json` plus its exact adapter
bytes before adoption. Confirm hashes and regular unlinked paths. Registry membership
and `--mask-projects` measurement do not authorize changing a consumer.

Development directory links observe canonical source changes immediately after
integration. An isolated authoring worktree protects them from intermediate edits.
Pinned consumers retain their selected artifact: use an explicitly approved scoped
MASK update/selection operation, preview it and apply its matching plan guard.
Do not invoke unqualified `mask update` to adopt one consumer: it advances the
legacy shared source for all legacy consumers. Do not mix a new canonical renderer
with a consumer's older pin. Invoke the renderer from the selected skill artifact.

For ordinary selected link reconciliation, use `mask plan --project ROOT --json`
and `mask apply --project ROOT --expect-plan-hash HASH --json`. A pin update is a
separate operation, not an ordinary link apply; consult the current capability and
CLI contract for `update --project ROOT` and its revision intent.

## Account for active work, then render

Inventory admitted runs and native/companion sessions before regeneration. Collect
old assignments or explicitly reissue them with original route evidence retained.
The renderer inventories local admitted run orders and refuses changed output while
an agent stage is uncollected. External/native sessions require integrator inventory;
there is no global session registry or automatic hot migration. Existing frozen
orders keep exact role/model/effort evidence, including the former deep meaning of
`rfc-worker`. A new generic worker launch means standard; it is not a resume API.

```sh
python /selected/implement-rfc/scripts/render_runtime_adapters.py --repo-root ROOT --check
python /selected/implement-rfc/scripts/render_runtime_adapters.py --repo-root ROOT
python /selected/implement-rfc/scripts/render_runtime_adapters.py --repo-root ROOT --check
```

The initial check may report stale or retired files; it never writes. Rendering
preflights all current and retired destinations against project ownership, generator
markers and prior hashes, including linked parents. Modified/unowned files remain
untouched. Only clean obsolete owned files are retired. The final manifest is
published last. A pending publication record means the set is incomplete: do not
launch native agents from it. Companion/new slice launches refuse pending output.
Retry with the same source and configuration; changed settings or user edits refuse.
Never remove the pending record manually to conceal partial publication.

Check success establishes generated bytes and requested routes. It does not establish
native reload, actual serving model/effort, quality equivalence or subscription savings.
Use plain Claude `xhigh`, preserve primary settings and processing speed, and verify
the declared CLI floor before any separately authorized serving trial. No automatic
CLI upgrade, model fallback, quota reset or purchase is part of adoption.

## Rollback boundary

Retain the expressly selected previous source/artifact and owned adapter snapshot.
First finish or reconcile any pending publication with its original inputs. For an
explicitly requested rollback, inspect that every current artifact still matches the
current owned manifest and has safe regular paths, then restore only the selected
prior artifacts/settings and matching manifest from the verified snapshot. Refuse
any user edit, ownership mismatch or linked path before restoring anything. The old
renderer alone does not provide this newer hash-preflight guarantee; do not use it
as a force-overwrite workaround. Use the supported scoped MASK flow for reverting a
pin. Source authoring rollback is a reviewed Git change, never reset/stash of user
work. Keep history, usage and earlier evidence intact. No blanket agent-directory
removal, registry-wide rewrite or claim that running agents reloaded is implied.
